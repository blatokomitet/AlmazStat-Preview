Продолжаем AlmazStat.

Текущий статус:
- главная страница уже показывает реальные матчи;
- пользователь может выбрать fixture;
- экран одного матча уже существует;
- backend подключён к API-Football;
- дизайн AlmazStat уже утверждён.

Теперь нужно сделать ПОЛНОЦЕННУЮ АНАЛИТИКУ ВЫБРАННОГО МАТЧА.

ВАЖНО:
НЕ переделывать визуальный стиль.
НЕ добавлять fake data.
НЕ добавлять OpenAI.
НЕ добавлять React / Next.js / TypeScript.
Сохраняем HTML + CSS + JS + Express.

========================================
1. BACKEND /api/match
========================================

Расширь существующий:

GET /api/match?fixture=FIXTURE_ID

Backend должен получить fixture и определить:
- homeTeamId
- awayTeamId
- leagueId
- season

Затем получать реальные данные API-Football.

Нужные источники:

A. fixture details
B. prediction
C. последние 5 матчей home team
D. последние 5 матчей away team
E. последние H2H
F. standings
G. odds — только если доступны

Нормализуй данные.

Не отправляй frontend огромные raw API responses.

========================================
3. ОБЗОР
========================================

Вкладка "Обзор" должна показывать реальные данные.

Верх:
- league
- date/time
- status
- teams
- logos
- score

Секция "Главный прогноз":

Использовать только API-Football prediction.

Показать:
- winner / predicted outcome
- advice
- home %
- draw %
- away %

ВАЖНО:
проценты API могут приходить строками типа "45%".
Нужно безопасно обработать.

Если prediction нет:
"Прогноз недоступен"

НЕ писать:
"наша модель"
"AI model"
"AlmazStat predicts"
если это данные API-Football.

Можно писать:
"Прогноз API-Football"

========================================
4. КЛЮЧЕВЫЕ ПОКАЗАТЕЛИ
========================================

Показывать только реально существующие показатели.

Например:

- ожидаемый / прогнозный счёт:
  prediction.goals.home
  prediction.goals.away

- under/over:
  prediction.under_over

- форма home
- форма away

Форму вычислить самостоятельно по последним 5 матчам:

W = 3 очка
D = 1
L = 0

Максимум за 5 матчей = 15.

Form percentage:
points / 15 * 100

Если матчей меньше 5:
делить на фактический максимум:
gamesCount * 3

Не придумывать данные.

========================================
5. ФОРМА
========================================

Вкладка "Форма".

Показать home и away отдельно.

Каждый матч:
- date
- opponent
- H / A
- score
- W / D / L
- league name, если удобно

Результат W/D/L считать относительно выбранной команды.

Пример:
если Arsenal был away и выиграл 2:1:
Arsenal = W.

Показывать до 5 последних матчей.

========================================
6. ОЧНЫЕ
========================================

Вкладка "Очные".

Показывать последние H2H.

Каждая строка:
- дата
- home team
- away team
- score
- tournament/league

До 5 последних матчей.

Если данных нет:
"История очных встреч недоступна"

========================================
7. ТАБЛИЦА
========================================

Не нужно рендерить всю таблицу лиги.

Найди строки home и away команд и покажи сравнительную карточку.

Для каждой:
- rank
- team
- played
- win
- draw
- lose
- goalsFor
- goalsAgainst
- goalDifference
- points
- form, если API даёт

Если standings отсутствуют:
"Таблица недоступна для этого турнира"

========================================
8. КОЭФФИЦИЕНТЫ
========================================

Вкладка "Коэффициенты".

Использовать только реальные odds API-Football.

Чтобы не перегружать UI:
показывать приоритетно рынки:

- Match Winner
- Goals Over/Under
- Both Teams Score
- Double Chance

Если этих рынков нет:
показывать первые доступные.

Для каждого:
- bookmaker
- market
- option
- odd

НЕ рассчитывать value betting.
НЕ создавать свои коэффициенты.
НЕ придумывать bookmaker.

Если данных нет:
"Коэффициенты недоступны"

========================================
9. DATA QUALITY RISK
========================================

Вкладка "Риск".

Это НЕ риск ставки.

Рассчитывать Data Quality Risk по наличию 6 источников:

fixture
prediction
form
h2h
standings
odds

Каждый доступный источник = 1.

availableSources = сумма.

risk score:

6/6 = 0
5/6 = 17
4/6 = 33
3/6 = 50
2/6 = 67
1/6 = 83
0/6 = 100

Уровни:

0–33:
LOW DATA RISK

34–66:
MEDIUM DATA RISK

67–100:
HIGH DATA RISK

Показать список:

✓ Fixture
✓ Prediction
✓ Form
✕ H2H
✓ Standings
✕ Odds

и краткое объяснение:

"Индекс показывает полноту аналитических данных, а не вероятность исхода матча."

========================================
11. LOADING / ERROR
========================================

Во время загрузки:
не показывать старые данные предыдущего fixture.

Использовать:
"Загрузка аналитики"

При backend error:
"Не удалось загрузить аналитику"

При частичном отсутствии данных:
экран матча всё равно должен работать.

Например:
fixture есть,
odds нет.

Это НЕ должно превращать весь экран в DATA ERROR.

========================================
12. API REQUEST OPTIMIZATION
========================================

ВАЖНО из-за лимита API-Football.

Добавь простой server-side cache в памяти.

Cache key:
fixture ID

TTL:
5 минут для live матчей
30 минут для pre-match
24 часа для finished матчей

Если точное разделение сейчас сложно:
используй единый TTL 10 минут как временный вариант.

Повторное открытие одного fixture не должно сразу делать все внешние API calls заново.

Не добавляй Redis/DB.
